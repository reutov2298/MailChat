# Кандидат UT: Почта Mail.ru

**Статус:** исследуется; адаптер не реализован, скорость и пригодность не измерены.

## 1. Разделять два разных продукта

Название Mail.ru объединяет как минимум два технически разных направления:

1. **Почтовый ящик Mail** — стандартные протоколы IMAP/SMTP. Официальная справка указывает `imap.mail.ru:993` и `smtp.mail.ru:465` с SSL/TLS. Это обычная электронная почта: сообщение адресуется ящику, а не публикуется как открытый объект по публичной ссылке.
2. **Платформа API Mail.Ru / Мой Мир** — отдельный набор API с OAuth и REST-методами, в том числе сообщения, лента, комментарии и гостевая книга. Наличие этих методов не означает, что они позволяют писать и читать почтовые письма Mail.

Источники:
- https://help.mail.ru/mail/login/mailer/
- https://api.mail.ru/docs/
- https://api.mail.ru/docs/guides/restapi/
- https://api.mail.ru/docs/reference/rest/

## 2. Почта Mail как транспорт

Предполагаемая схема:
- отправитель отправляет зашифрованный пакет как письмо на выделенный адрес получателя/технического ящика;
- получатель получает новое письмо по IMAP;
- после подтверждения получения письмо может быть перемещено в корзину или удалено в соответствии с возможностями протокола и политикой ящика.

Проверить:
- доступность IMAP IDLE и фактическую задержку уведомления о новом письме;
- скорость SMTP-приёма, доставки и появления письма в IMAP;
- лимиты размера, частоты, числа получателей и антиспам;
- авторизацию внешнего приложения и требования к паролям приложений/OAuth;
- удаление и синхронизацию удаления между клиентами;
- доступность серверов в сетях с ограничениями.

Преимущество: широко известный почтовый сервис и стандартные протоколы. Недостатки: аккаунт/адрес необходим, публичной доски и анонимного чтения по ссылке нет; задержка доставки почты может быть непредсказуемой. Поэтому это скорее надёжный асинхронный транспортный кандидат, чем публичная сверхбыстрая лента.

## 3. API платформы Mail.Ru / Мой Мир

В документации перечислены REST-методы `messages.post`, `messages.getThread`, `messages.getThreadsList`, `stream.post`, `stream.comment`, `stream.get`, `guestbook.post` и другие. Авторизация API основана на OAuth/session key; некоторые операции требуют разрешений пользователя.

Это может быть ближе к модели публичной ленты/комментариев, чем сама почта. Но необходимо отдельно установить:
- какие методы реально доступны новым приложениям и новым OAuth-клиентам;
- какие права может запросить standalone-приложение;
- существуют ли живые публичные объекты с чтением вторым аккаунтом;
- можно ли получать новые записи с короткой задержкой;
- допускают ли правила автоматизированное размещение машинных сообщений.

Не считать платформенные методы API интерфейсом к почтовому ящику Mail.

## 4. План PoC

1. Отдельно испытать IMAP/SMTP на двух независимых ящиках.
2. Измерить SMTP accept → IMAP visibility → получение клиентом.
3. Проверить IMAP IDLE против polling.
4. Проверить удаление после подтверждения и поведение при повторной доставке.
5. Отдельным экспериментом проверить доступность API «Мой Мир», не смешивая результаты с почтой.
6. Проверить сеть/операторов с ограничениями и зафиксировать конкретный регион, оператора, дату и результат.

**Предварительный вывод:** Mail.ru стоит изучать по двум веткам, но почта — не публичная доска. API «Мой Мир» потенциально интереснее для публичной публикации, однако его текущая доступность и пригодность требуют отдельного подтверждения.
