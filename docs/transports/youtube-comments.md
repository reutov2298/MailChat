# Кандидат UT: комментарии YouTube

**Статус:** гипотеза для исследования; адаптер не реализован и пригодность не подтверждена.

## 1. Идея

Проверить возможность использовать комментарии к заранее выбранному публичному видео как общедоступную ленту транспортных событий. Каждый клиент публикует отдельный зашифрованный пакет в виде комментария, а второй клиент периодически получает новые комментарии и извлекает пакеты.

Наличие Google-аккаунта упрощает знакомство с сервисом, но не означает, что API доступен без настройки OAuth и Google Cloud project.

## 2. Предполагаемый обмен

1. Участники согласуют video ID и параметры адаптера.
2. Отправитель формирует пакет UT и шифрует/подписывает его до передачи адаптеру.
3. Адаптер публикует пакет верхнеуровневым комментарием через commentThreads.insert.
4. Получатель запрашивает новые комментарии через commentThreads.list с videoId и сортировкой order=time.
5. Клиент фильтрует уже обработанные comment IDs, проверяет формат и передаёт байты в UT.
6. UT дедуплицирует пакет, MC выполняет криптографическую и прикладную проверку.
7. Подтверждение отправляется отдельным пакетом.
8. Удаление комментария возможно как необязательная очистка собственного комментария после надёжного подтверждения, но не является частью доставки.

Для первого PoC предпочтительны верхнеуровневые комментарии: это не требует заранее существующего parent comment ID для каждого сообщения. Ответы на комментарии можно проверить отдельно.

## 3. Официальные интерфейсы

- commentThreads.insert: https://developers.google.com/youtube/data/reference/rest/v3/commentThreads/insert
  - создаёт верхнеуровневый комментарий;
  - требует OAuth scope https://www.googleapis.com/auth/youtube.force-ssl;
  - документированная стоимость — 50 quota units.
- commentThreads.list: https://developers.google.com/youtube/data/reference/rest/v3/commentThreads/list
  - получает комментарии по videoId;
  - поддерживает order=time, maxResults до 100 и пагинацию;
  - документированная стоимость — 1 quota unit.
- Руководство: https://developers.google.com/youtube/data/guides/implementation/comments
- Квоты: https://developers.google.com/youtube/data/determine_quota_cost

В документации указана стандартная дневная квота 10 000 units для большинства остальных методов YouTube Data API на проект. Вставка комментария потребляет значительно больше квоты, чем чтение. Фактическую квоту и применимые ограничения нужно проверить в Google Cloud Console для тестового проекта.

## 4. Ключевые риски

- **Не мгновенная видимость.** Успешный ответ insert не доказывает, что комментарий уже виден всем клиентам.
- **Модерация и антиспам.** Комментарий может попасть в heldForReview/likelySpam, быть удалён или скрыт; обычный запрос списка по умолчанию возвращает опубликованные комментарии.
- **Ограничения аккаунта.** Для публикации требуется OAuth; аккаунт может быть не eligible или иметь ограничения.
- **Квоты.** Вставка стоит 50 units против 1 unit на list; частая отправка расходует проектную квоту.
- **Общий API project.** Квота привязана к проекту разработчика, а не автоматически предоставляется каждому пользователю за счёт его личного Google-аккаунта.
- **Условия использования.** Нужно отдельно проверить допустимость автоматизированного размещения машинных комментариев и не маскировать их под обычное человеческое общение.
- **Публичные метаданные.** Видны автор/канал, время, объект обсуждения, объём и ритм публикаций.
- **Удаление.** Оно не гарантирует, что получатель успел получить пакет; не использовать удаление как механизм доставки или конфиденциальности.
- **Зависимость от видео.** Комментарии могут быть отключены, видео удалено/ограничено, владелец может менять настройки.

## 5. План испытаний

1. Создать отдельный Google Cloud project и OAuth client для теста.
2. Проверить OAuth consent, доступ к YouTube Data API и авторизацию двух тестовых аккаунтов.
3. Выбрать тестовое видео с включёнными комментариями и проверить публикацию с двух аккаунтов.
4. Измерить интервал от ответа commentThreads.insert до появления комментария в commentThreads.list у второго клиента.
5. Повторить измерения при разных интервалах polling и размерах пакетов.
6. Проверить order=time, пагинацию, пропуски, повторное чтение и дедупликацию.
7. Проверить комментарии, задержанные модерацией, скрытые как spam, удалённые и заблокированные.
8. Проверить квоты, rate limits, ошибки OAuth и ограничения аккаунта.
9. Проверить удаление собственного комментария после подтверждённого получения.
10. Провести длительный тест и построить распределения T_publish, T_visibility, T_discovery и T_e2e.

## 6. Предварительная оценка

Потенциальные достоинства: публичная лента комментариев; машинный API чтения и публикации; временные метки и идентификаторы; потенциально широкая доступность сервиса.

Предварительные недостатки: OAuth и настройка API project; высокая цена публикации в quota units; возможная модерация и антиспам; отсутствие гарантии мгновенной видимости; зависимость от видео и политики YouTube.

**Вывод:** YouTube comments — интересный кандидат для PoC, но нельзя заранее считать его быстрым каналом. Главный эксперимент — измерить реальную задержку видимости и получения между двумя независимыми аккаунтами, а также частоту блокировок и расход квоты. До этого адаптер имеет статус «исследуется», не «поддерживается».
